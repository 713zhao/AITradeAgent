# AITradeAgent Database Architecture

The `AITradeAgent` utilizes three strictly separated SQLite databases to manage live trading, temporary external market data, and offline simulated testing. This separation prevents testing metrics from contaminating live portfolio logic. All databases are stored in the `finance_service/storage/` directory.

## 1. `portfolio.sqlite` (Live Portfolio & Trades)
**The Single Source of Truth for Live Operations.** 
* **Role:** Stores actual capital (`cash`), active `OPEN` positions, completed `trades` (buys and sells), and total realized/unrealized PnL. 
* **Consumers:** `PortfolioAgent`, `ExitAgent`, `app.py` (Dashboard API), and `scripts/heartbeat_report.py` (Hourly Report generator).
* **Update Frequency:** 
  * **Event-Driven:** Written to instantaneously whenever a trade order is successfully filled.
  * **Scheduled (15 minutes):** The `MarketScannerAgent` fetches live, real-time intraday quotes every 15 minutes during market hours and updates the `unrealized_pnl` column for all open positions so that portfolio valuations never lag.

## 2. `cache.sqlite` (Temporary Market Data)
**The External API Rate-Limiter.**
* **Role:** Caches incoming pricing quotes and metadata from external internet data providers (e.g., Yahoo Finance).
* **Consumers:** `DataAgent`.
* **Update Frequency:** Written to during daily universe discovery scans. It prevents the system from triggering HTTP bans while surveying hundreds of symbols. However, **15-minute live price checks explicitly bypass this cache** to ensure the portfolio's net asset value stays flawlessly accurate.

## 3. `backtest.sqlite` (Simulated Offline Runs)
**The Sandboxed Testing Environment.**
* **Role:** Stores simulated equity curves, strategy assessments, win rates, and generated metrics (e.g., CAGR, Sharpe ratio) specifically from offline historical strategy tests. It is never used to govern active trades.
* **Consumers:** `finance_service/tools/backtest.py`, `scripts/get_latest_backtest.py`, and the bottom "Assessment" portion of the `heartbeat_report.py`.
* **Update Frequency:** Only written to when a backtest is manually executed by an administrator.
  * **Recommendation:** It is highly recommended to run a fresh backtest on your active strategy **weekly or monthly**. Since market environments change (e.g., shifting from bull to sideways markets), updating the backtest ensures the performance metrics displayed in the Hourly Report accurately reflect the strategy's projected viability under current market conditions.

---

## Discrepancies and Report Generation
When viewing the Hourly Portfolio Report (generated by `scripts/heartbeat_report.py`), it integrates two distinct databases:
1. **The Top Half (Equity, Cash, P&L, Positions):** Scraped directly from the live `portfolio.sqlite` utilizing real-time API quotes.
2. **The Bottom Half (Strategy Assessment):** Reads solely from `backtest.sqlite` to display how the active strategy *should* perform theoretically over a multi-year horizon, serving as a baseline performance metric.
